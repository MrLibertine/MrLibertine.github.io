游戏配置表自动生成工具实现

2022-08-15 1.8k 字
Unity C# 工具

问题

游戏里到处都是配置表：装备属性、技能参数、关卡掉落、NPC 对话……策划在 Excel 里填数据，程序要把它变成代码里能用的东西。

最原始的做法：策划填好 Excel，程序手动转成 CSV 或手写 JSON，然后代码里 Load 进来按行解析。问题很明显——

每次策划加一列、改个字段名，程序都得跟着改读取逻辑，来回沟通成本高，还容易出 bug（表头拼错、索引对不上、类型搞混）。

我们需要一个工具：策划只管在 Excel 里填数据，跑一下工具，自动生成对应的 C# 类和序列化数据，代码里直接用。

整体思路

Excel 文件  →  工具读取  →  生成 C# 类 + 二进制数据  →  游戏运行时加载

分两步：

  1. 生成阶段（编辑器下）：读 Excel，按规则生成 .cs 文件和序列化后的数据文件（我们选的二进制，比 JSON 快、省空间）
  2. 运行时阶段：加载二进制数据，反序列化成强类型对象，直接拿属性访问

表结构约定

让策划按固定格式填，工具才能正确解析。Excel 里一张表长这样：

第一行 id name attack defense skillIds
第二行 int string int int int[]
第三行 编号 名称 攻击力 防御力 技能组
数据行 1001 铁剑 15 0 101,102
数据行 1002 皮甲 0 8 201

规则很简单：

  • 第一行是字段名，生成 C# 类的时候用它做属性名
  • 第二行是字段类型，决定 C# 属性的类型和序列化怎么读写
  • 第三行是中文注释，直接生成 <summary> 注释
  • 第四行开始是数据

生成 C# 类

工具读 Excel 的前三行就能生成类了。核心逻辑：

// 读取表头
var fieldNames = sheet.GetRow(0);  // id, name, attack, defense, skillIds
var fieldTypes = sheet.GetRow(1);  // int, string, int, int, int[]
var fieldDescs = sheet.GetRow(2);  // 编号, 名称, 攻击力, 防御力, 技能组

var sb = new StringBuilder();
sb.AppendLine("/// <summary>");
sb.AppendLine($"/// 自动生成，对应 {excelFileName}");
sb.AppendLine("/// </summary>");
sb.AppendLine($"public class {className}");
sb.AppendLine("{");

for (int i = 0; i < fieldNames.Count; i++)
{
    // 注释
    sb.AppendLine($"    /// <summary>{fieldDescs[i]}</summary>");
    // 字段
    sb.AppendLine($"    public {MapType(fieldTypes[i])} {fieldNames[i]} {{ get; set; }}");
}

sb.AppendLine("}");

生成的代码大概这样：

/// <summary>
/// 自动生成，对应 Item.xlsx
/// </summary>
public class ItemCfg
{
    /// <summary>编号</summary>
    public int id { get; set; }
    /// <summary>名称</summary>
    public string name { get; set; }
    /// <summary>攻击力</summary>
    public int attack { get; set; }
    /// <summary>防御力</summary>
    public int defense { get; set; }
    /// <summary>技能组</summary>
    public int[] skillIds { get; set; }
}

策划加了列，重跑一下工具就会重新生成 .cs，编译报错的地方就是要改的业务代码——比以前手动维护靠谱多了。

序列化选型

序列化就是把数据行写成二进制文件。我们选了最朴素的方式：手写 BinaryWriter / BinaryReader，不用 protobuf 也不用 MessagePack。

理由：

  • 依赖零，不引入第三方库
  • 性能足够好，二进制流直接内存复制
  • 类型严格可控，不会因为库的版本升级导致老数据读不出来
// 写入
public void Serialize(BinaryWriter writer, ItemCfg cfg)
{
    writer.Write(cfg.id);
    writer.Write(cfg.name);
    writer.Write(cfg.attack);
    writer.Write(cfg.defense);
    // int[] 先写长度，再写内容
    writer.Write(cfg.skillIds.Length);
    foreach (var id in cfg.skillIds)
        writer.Write(id);
}

// 读取
public ItemCfg Deserialize(BinaryReader reader)
{
    return new ItemCfg
    {
        id = reader.ReadInt32(),
        name = reader.ReadString(),
        attack = reader.ReadInt32(),
        defense = reader.ReadInt32(),
        skillIds = ReadIntArray(reader)
    };
}

序列化代码也是工具自动生成的，根据第二行的类型字段决定用 reader.ReadInt32() 还是 reader.ReadString()。

运行时查询

所有配置表加载后统一放在一个管理类里，按 id 索引：

public class CfgManager
{
    private Dictionary<int, ItemCfg> _items;

    public void Load()
    {
        // 读取二进制文件，批量反序列化
        var bytes = Resources.Load<TextAsset>("Configs/Item").bytes;
        using (var reader = new BinaryReader(new MemoryStream(bytes)))
        {
            int count = reader.ReadInt32();
            _items = new Dictionary<int, ItemCfg>(count);
            for (int i = 0; i < count; i++)
            {
                var cfg = ItemSerializer.Deserialize(reader);
                _items[cfg.id] = cfg;
            }
        }
    }

    // 业务代码里用
    public ItemCfg GetItem(int id) => _items.TryGetValue(id, out var cfg) ? cfg : null;
}

// 使用时
var cfg = CfgManager.Instance.GetItem(1001);
Debug.Log($"{cfg.name}: 攻击力 {cfg.attack}, 防御力 {cfg.defense}");

强类型的好处：打 cfg. 就有完整代码补全，传错字段编译报错，不用担心中途手滑写错字符串。

编辑器集成

在 Unity 编辑器里加了菜单项，策划改完 Excel 点一下就行：

[MenuItem("Tools/生成配置表")]
public static void GenerateAllConfigs()
{
    var excelDir = Application.dataPath + "/../Configs/Excel";
    var csDir = Application.dataPath + "/Scripts/Configs/AutoGen";
    var dataDir = Application.dataPath + "/Resources/Configs";

    // 清空旧文件
    if (Directory.Exists(csDir)) Directory.Delete(csDir, true);
    if (Directory.Exists(dataDir)) Directory.Delete(dataDir, true);
    Directory.CreateDirectory(csDir);
    Directory.CreateDirectory(dataDir);

    foreach (var excelFile in Directory.GetFiles(excelDir, "*.xlsx"))
    {
        // 1. 读 Excel
        var table = ReadExcel(excelFile);
        // 2. 生成 .cs
        GenerateCSharp(table, csDir);
        // 3. 生成二进制数据
        GenerateBinary(table, dataDir);
    }

    AssetDatabase.Refresh();
    Debug.Log("配置表生成完成");
}

读 Excel 用 EPPlus 还是 NPOI 都可以，我们选的 EPPlus（免费版够用），读取接口很简单：

几种特殊类型的处理

数组和列表

表里填 101,102,103 这种逗号分隔的格式，生成代码里自动处理：

// 序列化侧
private static int[] ParseIntArray(string cell)
{
    if (string.IsNullOrEmpty(cell)) return Array.Empty<int>();
    return cell.Split(',').Select(int.Parse).ToArray();
}

枚举

类型行写 enum:QualityType，工具就知道要生成枚举属性，并且在序列化代码里用 (QualityType)reader.ReadInt32() 做强转。

关联其他表

类型行写 ref:ItemCfg，表示这个字段是另一个表的 id。生成的注释里标注这是外键引用，方便使用方理解。

多行字符串

偶尔需要配大段文本。约定用 \n 当换行符，序列化时存成 string，运行时切分。

实际用了三年之后的感受

好处很明显：

  • 策划可以随便改表、加列，不用等程序手动对接
  • 属性访问有代码补全，打错字直接编译报错
  • 二进制数据比 JSON 加载快得多，内存占用也小
  • 够简单，全链路代码自己能维护

不够好的地方：

  • 每次小改都要重新生成整个 DLL 对应的序列化代码（二进制本身可以增量）
  • 复杂嵌套结构（表里套子表）支持起来比较麻烦，不如直接换用 ScriptableObject
  • 多人协作时 Excel 的 diff 基本没法看，策划之间改表冲突不好解决

考虑后面引入类似 Luban 的方案，但目前这个自研工具完全够用，也没有迁移的需求。

总结

这个工具的核心价值不在于技术多牛，在于把”程序手写配置读取代码”这件容易出错的事自动化了。代码量不大，几天就能写完，但省下来的沟通成本和 debug 时间持续了三年。

如果你项目里还在手动解析 Excel 转配置，可以考虑花一个工作日搭一套类似的东西——越早做越值。
