用 Cocos Creator 3.8 复刻我的 UI 性能实验室：10 个实验，零编辑器接线

2026-10-31 Cocos Creator 2.6k 字
性能优化 Cocos Creator UI TypeScript
在线演示：mrlibertine.github.io/cocos-perf-lab/
10 个可交互实验，全部数字都是运行时实时测出来的。建议桌面 Chrome / Edge 打开，1280 以上宽度。

画面太小看不清时，点右下角 ⛶ 全屏；也可以在新窗口单独打开。

之前用 Unity WebGL 做过一个 UI 性能实验室，把长列表、合批、对象池、遮罩断批、帧率分布这些容易出问题的点做成了可实时观察的形式。这次用 Cocos Creator 3.8.8 + TypeScript 完整复刻了一遍——不是抄三个片段，而是把那个工程的整体结构（入口 + 核心库 + 10 个页面）搬过来重写。

两个约束是刻意的：

  1. 零编辑器接线。场景里只有一个空节点挂一个 LabApp 组件，所有面板、按钮、滚动列表、遮罩全部用代码创建，没有任何 Prefab、没有 SpriteFrame 资源文件（圆角矩形和圆点都是运行时用 Texture2D 现生成的）。
  2. 命令行构建。项目文件是脚本生成 + 手写的，构建走 CocosCreator.exe --build，不依赖打开编辑器点按钮。

结果是 3,584 行 TypeScript、10 个页面、10 个核心模块。

下面挑几个有信息量的说。

虚拟列表：14 个节点滚 10 万条

content 高度按真实数据撑满（10 万 × 64px ≈ 6.4M px），滚动时由 content.position.y 反算可见区间，区间外回池、区间内摆位。跑起来常驻节点数是 14，Content 节点一次都没重建过。

有个细节值得记下来：content 高度按 10 万 × 64px 撑到 640 万像素。这个量级下 UITransform 的 float 精度还够用（Unity 侧同理），但再上一个量级就得做「分段偏移」——按段重置 content 的 y，同时补一个逻辑偏移量，否则滚动条百分比会开始抖。代码里只留了这条注释，没有实现，因为当前数据量用不到；我不想为了显得完整而写一段永远跑不到的代码。

合批：1 批 vs 160 批

160 个视觉完全一样的方块，只换贴图来源：

  • 共享图集（运行时从一张 4×4 图集里切）：1 批
  • 独立纹理（每个方块一张独立贴图）：160 批

这里踩了一个坑值得记下来：一开始把整块面板传进估算器，共享图集模式也测出「4 批 / 4 张纹理」。原因是系统字体的每个 Label 实例都持有自己的动态字型纹理，一个标题加一个脚注就顶掉两个批次。把 160 个方块单独挂到一个纯容器节点下、只统计这一层，才得到干净的数字——这件事本身就是 UI 图集优化的重点：Cocos 里系统字体的 Label 天然不并批，正式项目里必须换成位图字体或把 Label 独立管制。

遮罩：Stencil 是固定成本

同样 36 个方块，只改裁剪方式：

列 批次 说明
无遮罩 1 批 内容溢出到区域外也不会被裁
Mask（单层） 3 批 每个 Mask 固定 +2（写模板 + 还原），且与外部必然断批
Mask（嵌套两层） 6 批 两层 = +4，叠得更狠

这段和 Unity 的结论完全一致：UGUI 里的 RectMask2D 是廉价版本，Mask 走 Stencil 就贵；Cocos 只有 Stencil 这一条路，所以能用「更换内容显示范围」解决的就别上 Mask。

UI 框架：窗口栈是真的在跑

窗口栈按 Layer 插入而不是按创建顺序追加，弹窗队列保证同时只有一个模态糊在上面，事件总线做了泛型版和装箱版两条通路对照派发 10 万次。模态遮罩是真实铺满舞台的 Button，点上去会打日志告诉你「被挡住了」——不是画个半透明矩形假装拦截。

内存实验室：老实说，浏览器不给堆数据

这一页原本的设想和 Unity 版一样，测每轮循环在堆上留了多少垃圾。实测下来：performance.memory.usedJSHeapSize 在普通页面里只在 GC 检查点刷新，我特意分配 8MB Uint8Array 验证，读数一动不动（差值为 0）。也就是说，任何「堆净增长」的对比在浏览器里都是假的。

所以页面改成了：耗时是真实测的，分配数按循环里真实 new 出来的对象数标注，并且把这句话直接写在页面上：

  • 字符串拼接 20,000 轮：每轮新建 2 万个字符串
  • 预格式化缓存：只新建 64 个（查表复用）
  • 装箱 / 闭包：各 2 万个
  • for 循环基线：1 个

比编一个漂亮的「+1.2 MB」诚实，而且面试时这本身就是个可以展开讲的点——测量口径比数字重要。

移植时踩的 5 个坑

这部分是这次复刻最实在的收获，每条都是运行时「什么都看不到」或者「控制台一直报错」之后查出来的。

1. 运行时创建的节点默认不在 UI 层

new Node() 的 layer 是 Layers.Enum.DEFAULT（1073741824），而 UI 相机的 visibility 是 UI_2D（41943040）。全部代码建 UI 时，如果忘了设 node.layer = Layers.Enum.UI_2D，画面就是纯灰底——没有任何报错。我最后加了个兜底：

export function newUINode(name: string): Node {
    const n = new Node(name);
    n.layer = Layers.Enum.UI_2D;
    return n;
}
// 入口处递归兜底，防止漏网的节点
export function fixLayer(root: Node) {
    root.layer = Layers.Enum.UI_2D;
    for (const c of root.children) fixLayer(c);
}

2. Mask 和 Sprite 不能挂在同一个节点上

报错是 Can't add renderable component to this node because it already have one。遮罩必须是一个「带 Mask 的空包装节点 + 里面一层 Sprite」的结构，不能一个节点两件事都干。

3. Button.target 要的是 Node，不是 Sprite

Unity 里 Button.targetGraphic 接的是 Graphic 组件，Cocos 里 target 是 Node。写成 b.target = sprite 会在按下时炸在 Vec3.copy 里，报 Cannot read properties of undefined (reading 'x')。

4. 一次 stretch 不够，要挂 Widget 且 AlignMode.ALWAYS

想让背景和内容区跟着 Canvas 尺寸变，只在初始化时算一次像素是不行的——窗口 resize 后位置就错了。要挂 Widget 并把 alignMode 设成 ALWAYS。

5. setRect 是按父节点「当前」尺寸算的

这个坑最隐蔽：先创建窗口卡片（默认尺寸），子节点的横向拉伸按当时的父尺寸算好；等外层再调 setContentSize(344, 196)，标题栏还停在旧宽度上——表现就是标题栏缩成一小块、文字和骨架条挤在一起。

结论：先定父节点尺寸，再挂子节点。 所有布局函数都按这个顺序写。

手写项目 + 命令行构建

项目不是用编辑器新建的，是靠一个 Python 脚本生成 + 手写场景：

  • package.json（creator.version / uuid）、settings/v2/packages/project.json（设计分辨率 1280×720）、tsconfig.json
  • **每个资源都要有 .meta**：.ts.meta（ver 4.0.24, importer: typescript，uuid v4）、目录的 .meta（importer: directory）、场景的 .meta（importer: scene）
  • 场景 lab.scene 是一个 JSON 对象数组，手写时最麻烦的是组件里 __type__ 要填压缩后的脚本 uuid。Cocos 的压缩规则是「保留前 5 位十六进制，之后每 3 位压成 2 个 base64 字符」：
def compress_uuid(u):
    h = u.replace('-', '').lower(); out = h[:5]
    for i in range(5, 32, 3):
        a, b, c = int(h[i], 16), int(h[i+1], 16), int(h[i+2], 16)
        out += B64[(a << 2) | (b >> 2)] + B64[((b & 3) << 4) | c]
    return out

构建就是一行命令：

CocosCreator.exe --project E:\cocos\PerfLab `
  --build "platform=web-mobile;debug=false;startScene=<scene-uuid>;md5Cache=false"

两个环境上的坑：WorkBuddy 注入的 ELECTRON_RUN_AS_NODE 会让 CocosCreator（Electron 应用）直接把 --project 当非法参数，报 bad option: --project 然后秒退；另外环境里存在 HTTP_PROXY / http_proxy 这种大小写重名的键时，PowerShell 的 Start-Process 会报「字典中的关键字重复」。启动前清掉这些环境变量就好了。

产物 4.3 MB，直接丢进 Hexo 的 source/cocos-perf-lab/，构建时原样拷贝到 public/，不需要额外配置。

最后

复刻这件事的价值不在于「Cocos 也能做」，而在于同一批性能规律换了引擎还成立：虚拟列表的复用逻辑、合批的四条件、Stencil 的固定代价、P95 才是玩家感受，这些跟引擎无关，换到 LayaAir 也是一样的结论。
