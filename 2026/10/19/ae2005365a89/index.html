Unity 客户端 UI 性能实践：虚拟列表、合批与框架设计

2026-10-19 Unity 1.2k 字
Unity WebGL 性能优化 UGUI

一个可以直接在浏览器里运行的 Unity 客户端工程，把 UGUI 里最容易出问题的几块——长列表、对象池、DrawCall 合批、UI 框架、内存分配、遮罩、帧率分布——做成了可实时观察的形式：每一项都能切换参数，当场看帧率、节点数、批次、堆分配的变化。

整个工程零美术资源依赖：贴图、图集、UI 全部由代码在运行时生成，clone 下来就能跑。

在下面直接体验（首次加载需要下载约 10MB 运行时，请稍等）：

建议用电脑浏览器打开；加载后点击画面获取键盘焦点，画面右上角有全屏按钮（Esc 退出）。
也可以在新窗口单独打开。

演示内容

基础优化

  1. 虚拟列表 —— 10 万条数据的列表，常驻只有 14 个节点：滚动时”绑定次数”持续上涨，”创建次数”保持不变，说明节点是在复用而不是反复创建。
  2. 对象池压测 —— 同一套粒子动画，直连 Instantiate 与走池复用分两轮跑，实时对比创建次数、每帧耗时、单帧峰值，最后自动给出结论。
  3. DrawCall 合批 —— 160 个视觉完全相同的元素，共享图集模式下只有 4 个 Batch，切到独立纹理立刻飙到 160+，可以直观看到合批是怎么被打断的。
  4. 技能战斗 —— 弹道、范围光圈、飘字全部走对象池，1x~12x 并发可调，实时监控帧率与活跃对象数。

框架与工程深度

  1. UI 框架 —— 窗口栈是真实在跑的：按 Layer 插入排序（而不是谁后创建谁在上）、模态弹窗阻断下层、三个弹窗请求排队串行显示、事件派发用泛型。页面右侧可以直接跑 10 万次派发，对比泛型与 object 装箱版的耗时和堆分配。
  2. 内存实验室 —— 六种常见写法各跑 2 万轮，测量托管堆净增长：字符串拼接、StringBuilder 复用、装箱、闭包捕获、LINQ、数组遍历。柱状图长度就是垃圾产生量。
  3. 遮罩断批 —— 三列内容完全一致（同图集、同色、同尺寸），只换裁剪方式。元素从 18 增到 72，批次数几乎不变说明合批生效；而 Mask 那列始终比 RectMask2D 多出固定的 2 批。
  4. 帧分析 —— 最近 600 帧的直方图、P50 / P95 / P99、最慢帧、超过 33ms 的卡顿计数。还提供一个”压力注入”开关，故意每帧烧 CPU，看 P95 立刻变脸。

几个值得说的技术点

  • 层级由数据决定，不由创建顺序决定：后打开的 HUD 如果直接 Add 到列表末尾，会盖住已经开着的弹窗。所以压栈时按 UILayer 枚举值插入，再同步 siblingIndex，而不是依赖 Canvas.sortingOrder（Overlay 下每多一个 sortingOrder 就多一次 Canvas 切分）。
  • 值类型事件不要走 object：Publish<T>(T evt) 是泛型方法，T 为 struct 时编译期生成专用代码，全程无装箱；换成 Publish(object) 每次派发都在堆上留一块垃圾。战斗里一帧几百个伤害事件，这个差别会被放大到 GC 层面。
  • 合批监控按 UGUI 规则反推：运行时读不到 UnityStats，所以按”同材质 + 同贴图连续”的合批条件自己估算 Batch 数，且遇到 Mask 时按 stencil 规则 +2 并强制断批。只统计演示区域，避免字体贴图干扰统计结果。
  • RectMask2D 与 Mask 的差别在模板缓冲：前者只往材质传一个 _ClipRect 参数，不换材质、不加批次；后者要写模板再还原，每个至少 +2 个 DrawCall，并且子树与外部一定断批。所以滚动列表一律用 RectMask2D，Mask 只留给圆形头像这类非矩形裁剪。
  • 帧率要看分布不看均值：59 帧 10ms 加 1 帧 200ms，均值依然是”稳 60”，但玩家感受到的是那一次卡顿。所以记录 P95 / P99 与超阈值次数，单帧超标时打一条上下文快照，比事后靠玩家描述去猜有效得多。
  • 零资源依赖：所有 UI 由一套自研 UIKit 在运行时构建，底图三张合一张运行时图集（带 4px 防渗色 padding），避免贴图边缘出现细缝。
  • WebGL 下的中文字体：WebGL 拿不到系统字体，CreateDynamicFontFromOSFont 直接返回 null，中文会全部变成方块。解决办法是把中文字库直接打进包内，通过 Resources 加载。
  • 部署适配 GitHub Pages：Pages 不提供自定义响应头，Brotli 压缩和线程支持（依赖 COOP/COEP）都用不了，因此构建采用 Gzip + Decompression Fallback（解压逻辑内置在 loader 里，由 JS 自行解压），包体控制在 10MB 左右。

工程源码与 Windows 免安装版同步提供，可以对照源码查看每页的实现细节。
