Unity 客户端面试 Demo（WebGL 在线体验）

2026-10-19 Unity 585 字
Unity WebGL 性能优化 UGUI

找工作期间做的一个可运行的 Unity 客户端 Demo，把简历里最容易被追问的几块能力（UI 框架、虚拟列表、对象池、DrawCall 合批、技能战斗表现）做成了可以现场操作的页面。整个工程零美术资源依赖：贴图、图集、UI 全部由代码在运行时生成。

直接在下面就能玩（首次加载需要下载约 10MB 运行时，请稍等）：

建议用电脑浏览器打开；加载后点击画面获取键盘焦点，右上角可全屏。

演示内容

  1. 虚拟列表 —— 10 万条数据的列表，常驻只有 14 个节点，滚动时”绑定次数”上涨而”创建次数”不涨，直观展示区间回收复用。
  2. 对象池压测 —— 同一套粒子动画，直连 Instantiate vs 池复用，实时对比创建次数、每帧耗时、单帧峰值，自动给出结论。
  3. DrawCall 合批 —— 160 个视觉相同的元素，共享图集模式只有 4 个 Batch，切到独立纹理直接飙到 160+，现场看合批是怎么被打断的。
  4. 技能战斗 —— 弹道、范围光圈、飘字全部走对象池，1x~12x 并发可调，实时帧率与活跃对象数监控。

几个值得说的技术点

  • 零资源依赖：所有 UI 由一套自研 UIKit 在运行时构建，底图三张合一张运行时图集（带 4px 防渗色 padding），不怕现场丢资源。
  • 合批监控按 UGUI 规则反推：运行时无法读取 UnityStats，所以按”同材质 + 同贴图连续”的合批条件自己估算 Batch 数，并且只统计演示网格区域，避免字体贴图噪声污染数字。
  • WebGL 版的中文坑：WebGL 拿不到系统字体，CreateDynamicFontFromOSFont 直接返回 null，中文全是豆腐块。所以把中文字库直接打进包内（Resources 加载），这也是所有带中文的 WebGL 项目都会踩的坑。
  • 部署适配 GitHub Pages：Pages 不给自定义响应头，Brotli 必挂、多线程（COOP/COEP）也开不了，所以构建用了 Gzip 压缩 + Decompression Fallback（pako 内置进 loader，由 JS 自己解压），包体控制在 10MB 左右。

工程源码与 Windows 免安装版（Demo.exe）另有交付，面试时可以现场打开 Unity 源码逐页讲实现。
